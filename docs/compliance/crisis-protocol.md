# 心理危机分级与转介流程

> 本文件是流程模板，必须由学校心理中心、学生工作部门、法务共同审核。
> 话术与联系方式在 `config.json` 的 `crisis` 字段配置，代码中不内置未经审核的号码。

## 1. 原则

- 不拦截求助：检测到危机内容时，不阻断对话，不用“系统拒绝回答”结束。
- 不替代专业：AI 不做诊断、不做危机干预、不承诺保密。
- 不自动上报：默认不通知家长、辅导员或任何第三方。
- 最小留存：高风险内容不写审计原文，只记录 `crisisLevel`。
- 固定话术：高风险场景不调用模型，避免小模型自由发挥。

## 2. 分级

| 级别 | 触发 | 系统行为 |
| --- | --- | --- |
| 高 | 自杀、轻生、自伤、自残、结束生命、活不下去、危机干预等 | 强制本地；不调用模型；固定转介话术；红色横幅；审计只记 `high` |
| 中 | 心理测评、心理咨询、抑郁、焦虑、失眠、情绪低落、厌学、崩溃等 | 本地处理；正常回复；黄色提示与转介资源 |
| 低 | 心理健康课程、科普、活动通知 | 正常路由，不触发危机流程 |

## 3. 高风险固定话术

默认模板不依赖具体地区：

1. 表达关心，不评判。
2. 说明 AI 不能替代专业帮助。
3. 推荐全国心理援助热线 12356，并提示“如当地未开通，请拨打 120 / 110”。
4. 学校心理中心、辅导员作为可选补充，由 `config.crisis` 填写。
5. 提醒告诉身边一个可信任的人。
6. 如有立即伤害自己的打算，拨打 120 / 110 或去最近急诊。
7. 不承诺绝对保密，也不威胁上报。

学校可在 `config.crisis.message` 中完全覆盖模板。

## 4. 人工流程建议

系统只负责识别与转介，后续由学校按既有危机干预制度处理。建议明确：

- 谁负责接收学生主动求助
- 什么情况下启动人工介入
- 是否需要告知监护人，依据是什么
- 如何记录、保存、销毁相关材料
- 多久复盘一次误报与漏报

## 5. 不该做的事

- 不要在检测到高风险后静默阻断。
- 不要让模型生成安慰性承诺或诊断性判断。
- 不要在未告知学生的情况下自动通知家长或辅导员。
- 不要把危机原文写入审计日志或云端请求。
- 不要用“系统检测到你情绪不好”这类标签化语言。

## 6. 审核清单

- [ ] 话术由心理中心审核
- [ ] 联系方式准确、可用、24 小时可用
- [ ] 转介流程与学校现有制度一致
- [ ] 告知书已向学生发布
- [ ] 审计留存期限已确定
- [ ] 误报/漏报复盘机制已建立

## 7. 配置示例

```json
"crisis": {
  "enabled": true,
  "hotline": "当地 24 小时心理援助热线",
  "counselingCenter": "学校心理中心电话/地址",
  "counselorContact": "辅导员联系方式",
  "message": ""
}
```

`message` 为空时使用默认模板；填写后完全覆盖默认模板。
